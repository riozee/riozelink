# RiozeLink

**[English](README.md) · 日本語**

RiozeLink は、あなたのパソコンで動かす小さなデーモンです。ブラウザの [riozeOS](https://rioze.dev)
へ、暗号化された専用の一本のリンクを開きます。そのリンクを通して riozeOS は、選んだフォルダを
ドライブとして読み書きし、AnkiConnect と話し、Ollama や OpenAI 互換のエンドポイントへ自分の
キーで AI のチャットを送れます。インターネット上のサーバーも、アカウントも要りません。

```text
 あなたのパソコン                       ブラウザ
┌──────────────────────┐              ┌──────────────────────┐
│  ~/Notes      ───────┼── WebRTC ────┼─► /riozeos/drives/   │
│  AnkiConnect  ───────┼── 暗号化 ────┼─► notes              │
│  Ollama       ───────┼── DataChannel┼─► Anki パネル        │
│  API キー (0600)     │              │   AI パネル          │
└──────────────────────┘              └──────────────────────┘
        riozelink                          riozeOS アプリ
```

## なぜ使うのか

- **本物のファイル。** パソコンのフォルダが riozeOS のドライブとして現れます。読み、書き、名前を
  変え、消せます。riozeOS 自身のファイルはブラウザの中にあり、ブラウザはいつでもそれを消せます。
  共有フォルダはあなたのディスクなので、置いた場所にそのまま残ります。
- **プラグインに振り回されない Anki。** AnkiConnect はパソコンのループバックでしか待ち受けません。
  デーモンはその同じパソコンで動いているので、呼び出しをそのまま届けます。
- **モデルのある場所で動く AI。** Ollama はあなたのパソコンで動いています。OpenAI のキーも同じ
  パソコンに、あなただけが読める権限で保存されます。riozeOS が目にするのは `sk-...1234` までです。

## 必要なもの

- [Bun](https://bun.sh) 1.2 以降。デーモンは Bun が直接実行する TypeScript です。
- このパソコンへ LAN 越しに届くブラウザの riozeOS。
- 任意で、[AnkiConnect](https://foosoft.net/projects/anki-connect/) アドオンを入れた Anki と、
  ローカルモデルを使いたい場合の [Ollama](https://ollama.com)。

## インストール

```sh
git clone https://github.com/riozee/riozelink.git
cd riozelink
bun install
```

インストールせずに試すなら、そのまま起動できます。

```sh
bun run start
```

`riozelink` を `PATH` に置きたくなったら次をどうぞ。

```sh
bun link
```

GitHub から直接入れることもできます。

```sh
bun install -g github:riozee/riozelink
```

## はじめての接続、順番に

**1. デーモンを起動する。**

```sh
riozelink
```

ターミナルに小さなパネルが出ます。次の手順で必要なものは、そこに全部書いてあります。

```text
RIozeLink 0.1.0 · listening
address  ws://192.168.1.20:4287
code     K7F2-9QXW (14m 03s left)
clients  no clients yet
shares   none yet
config   ~/.config/riozelink/config.json
```

**2. フォルダを共有する。** 別のターミナルからでも、あとで riozeOS のアプリからでも構いません。

```sh
riozelink folders add ~/Notes --label Notes
```

**3. riozeOS からつなぐ。** riozeOS を開き、**RiozeLink** アプリを起動します。アドレスを貼り、
コードを貼り、Connect を押します。ブラウザと同じマシンのアドレスなら `ws://localhost` でも
大丈夫です。

この裏側では次の順番で進みます。

1. ブラウザが ECDSA P-256 の鍵ペアを作り、秘密鍵は取り出せない形のまま IndexedDB に置きます。
   ブラウザの外には出ません。
2. ブラウザがコードの名前の部屋に入り、WebSocket のシグナリングで WebRTC の offer と answer を
   交換します。ここは紹介だけです。会話そのものは DTLS で暗号化された DataChannel の上を
   通ります。
3. そのチャンネルでブラウザが `auth:hello` を送ります。デーモンは自分の公開鍵とノンス、そして
   ブラウザのノンスへの署名を返します。ブラウザはそれを検証するので、ネットワーク上の別の
   何かではなく、あなたのデーモンにつながったと確信できます。
4. ブラウザはデーモンのノンスに自分の鍵で署名し、コードと一緒に `auth:pair` を送ります。
   デーモンは両方を確認し、クライアントのフィンガープリントを `authorizedClients` に書き
   ます。
5. コードはその場で引退します。次の接続は保存された鍵を使うので、そのブラウザでコードを打つ
   のは一度きりです。

**4. 使う。** 共有したフォルダは riozeOS のファイルエクスプローラーで
`/riozeos/drives/notes` として現れます。そこでする読み書きは、そのまま選んだフォルダに届き
ます。

## 日常の使い方

### 再接続

riozeOS のアプリを開いて Connect を押すだけです。知っているブラウザはコードを求められず、
署名で自分を証明します。アドレスはブラウザごとに覚えられるので、実際にはワンプレスです。

デーモンを再起動しても身元は変わりません。ブラウザは最初のペアリングで見たホストの
フィンガープリントを覚えていて、接続のたびに照合します。同じアドレスに別のマシンが答えた
場合、アプリはそこで止まります。

### 共有フォルダを増やす

ターミナルから。

```sh
riozelink folders add ~/Documents/recipes
riozelink folders list
riozelink folders remove recipes
```

riozeOS 側では RiozeLink アプリの **Drives** タブが同じことをリンク越しに行います。認可された
クライアントはフォルダを追加できます。これは本物の権限なので、ペアリングは「このマシンへの
鍵を渡すこと」だと思ってください。取り戻したいときは、設定ファイルの `authorizedClients`
からそのクライアントを消してデーモンを再起動します。

### Anki

アプリの **Anki** タブか設定ファイルで有効にします。デーモンは `127.0.0.1:8765` を調べ、
Anki デスクトップが本当に開いているかを報告します。有効な間、アプリが求めた AnkiConnect の
操作はそのまま転送されます。無効な間は、ペアリング済みのクライアントにも `denied` と答え
ます。

コレクションの中身がどこかに保存されることはありません。呼び出しは転送され、それきりです。

### AI

**AI** タブには 2 つのプロバイダーがあります。

- **Ollama。** エンドポイントの初期値は `http://127.0.0.1:11434` です。キーは不要で、チャットは
  トークンごとに流れてきます。
- **OpenAI 互換。** `stream: true` の `/v1/chat/completions` を話すエンドポイントなら、自前の
  ゲートウェイでも構いません。キーは暗号化された回線を一度だけ渡り、`0600` の権限で
  `config.json` に書かれ、二度目以降は伏せ字でしか読まれません。

## 設定ファイル

初回起動で `~/.config/riozelink/config.json` が作られます。手で編集する前提のファイルです。
読めない値は既定値に戻るだけで、デーモンが止まることはありません。

```json
{
	"version": 1,
	"hostName": "rioze-macbook",
	"port": 4287,
	"folders": {
		"notes": { "label": "Notes", "path": "/Users/rioze/Notes" }
	},
	"anki": { "enabled": false, "port": 8765 },
	"ai": {
		"provider": "ollama",
		"endpoint": "http://127.0.0.1:11434",
		"model": "llama3.2",
		"apiKey": ""
	},
	"authorizedClients": {
		"9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08": {
			"label": "Browser",
			"pairedAt": 1789000000000
		}
	}
}
```

同じ場所に `identity.json` があり、デーモン自身の鍵ペアが入っています。これは大切に。差し替える
と、すべてのブラウザがもう一度コードを求めるようになります。

`RIOZELINK_CONFIG_DIR` を設定すると両方のファイルを別の場所へ移せます。テストが本物のホーム
ディレクトリに触らないのも、これを使っているからです。

## コマンド

| コマンド                                         | すること                                                    |
| ------------------------------------------------ | ----------------------------------------------------------- |
| `riozelink`                                      | デーモンとターミナルパネルを起動します。                    |
| `riozelink --port 5000 --bind 0.0.0.0`           | 別のポートやインターフェースで起動します。                  |
| `riozelink --stun stun:stun.l.google.com:19302`  | STUN サーバーを足します。LAN の外に出るリンク用です。       |
| `riozelink --quiet`                              | アドレスとコードを一度だけ出し、あとはログ行だけ流します。  |
| `riozelink folders list`                         | 共有中のフォルダを表示します。                              |
| `riozelink folders add <path> [--label Notes]`   | フォルダを共有します。                                      |
| `riozelink folders remove <id>`                  | 共有をやめます。                                            |
| `riozelink status`                               | 設定ファイルの要約を、クライアントも含めて表示します。      |

パネルでは `n` がコードの交換、`h` が最初の接続の手引き、`q` がデーモンの停止です。

## 仕組み

### 部品たち

| 部品               | ある場所                        | すること                                                                |
| ------------------ | ------------------------------- | ----------------------------------------------------------------------- |
| シグナリングサーバー | `src/signaling.ts`            | 部屋の名前をコードかホストの指紋と照合し、SDP と ICE を中継します。     |
| WebRTC リンク      | `src/peer.ts`                   | ブラウザの offer に答え、候補を流し、DataChannel を渡します。           |
| 認証               | `src/session.ts`                | hello、proof、pairing。ほかのメッセージはこの後ろで待ちます。           |
| ファイルシステム   | `src/vfs.ts`, `src/sandbox.ts`  | パスの柵、分割読み書き、パートファイル、変更の監視。                    |
| Anki               | `src/anki.ts`                   | トグルひとつと、ループバックへの POST。                                 |
| AI                 | `src/ai.ts`                     | 2 つの方言を 1 つのストリームに。キーはここに残ります。                 |
| ワイヤ契約         | `src/protocol.ts`               | 両側がクライアントとディスパッチャを組み立てる、ただ 1 つのファイル。   |

riozeOS 側は riozeOS リポジトリの `com.riozelink.svelte` アプリです。そのリモートバックエンドは
ローカルのファイルシステムと同じ `VfsBackend` を実装しているので、ファイルエクスプローラーは
ドライブが遠くにあることを知りません。

### ファイルを 1 つ読む、その一生

1. riozeOS がファイルシステム層に `/riozeos/drives/notes/sub/list.txt` を求めます。
2. マウントテーブルが、パスがリモートドライブの中だと気づき、接頭辞を外してリモートバック
   エンドに渡します。バックエンドが見るのは `/sub/list.txt` です。
3. バックエンドは共有 ID とオフセットを添えて `vfs:read` を送り、最大 45 KB を求めます。
4. デーモンはパスを正規化し、存在する一番深い部分までさかのぼって、OS にその実体の場所を
   尋ねます。実体が共有フォルダの外なら、呼び出しごと拒否します。シンボリックリンクで
   何かを持ち出すことはできません。
5. デーモンはその一片を読み、base64 にして返します。クライアントは `done` が来るまで
   頼み続けます。

1 メッセージ 45 KB というのは、切りのいい数字ではなく、理由のある数字です。base64 で 3 割
ほど増え、WebRTC の実装によっては 64 KB がメッセージの上限なので、その下に収める必要が
あります。どこでも通る一片は、紙の上で速い一片に勝ります。

### ファイルを 1 つ書く、その一生

書く方向は慎重です。各一片は、対象と同じフォルダの隠しファイル
`<name>.riozelink-part-<id>` に落ちます。最後の一片が届くまで本物のファイルには触らず、
最後の仕上げは rename 一回だけです。rename は起きるか起きないかのどちらかなので、途中で
切れたアップロードが「本物のつもりの半端なファイル」を残すことはありません。

パートファイルはクライアントからは見えず、持ち主のセッションが終わると消えます。途中で
kill されたデーモンは 1 つ残すことがあります。次の起動が 1 時間より古いものを掃除します。

### 再接続と身元

デーモンは最初の起動で ECDSA P-256 の鍵ペアを `identity.json` に作ります。ブラウザは最初の
ペアリングで見たフィンガープリントを固定します。以後の接続は毎回それを照合するので、同じ
アドレスの別のマシンが静かに取って代わることはできません。デーモンの指紋を名前にもつ部屋が
あるのは、この戻り道のためです。

ペアリングコードは寿命の短い一度きりの秘密です。15 分で消え、誰かがペアリングした瞬間に
引退し、10 回間違えると交換されます。その後は誰にも、肩越しに見た人にも、使えません。

### 複数のブラウザを同時に

1 つのデーモンが複数の riozeOS を同時に相手にします。接続はそれぞれ自分のセッションを持ち、
認証状態も、アップロード中のパートファイルも、AI のストリームも別々です。デーモンが
クライアント同士を引き合わせることはありません。共有されるのは接続数という数字だけで、
ほかのクライアントについて知れるのもそれだけです。

### 変更を眺める

共有フォルダはホスト側で監視されます。変更は 0.25 秒ぶんまとめられ、接続中のすべての
クライアントへ `vfs:changed` として届きます。`fs.watch` は作成と削除を見分けられないので、
rename には `stat` で答えます。名前がいま存在するなら、現れたのです。純粋な rename は削除と
作成として届きます。クライアントの場所から見れば、それは本当のことです。

## セキュリティについて、正直に

このリンクは仕組みとして閉じています。DataChannel は 2 つのピアの間で DTLS により暗号化され
るので、シグナリングサーバーが運ぶのは紹介だけです。どのセッションも、ほかのどんな
メッセージに答える前に対話の認証を通ります。両側が相手の選んだノンスに署名するので、再生や
中間者を挟むことはできません。

デーモンが誰に頼まれてもしないこと。

- 共有したフォルダの外のパスに触れること。
- シェルコマンドの実行、ポートを開くこと、ネットワークの探索。
- API キーを伏せ字以外の形で返すこと。
- 設定ディレクトリの外に自分のファイルを書くこと。

知っておくと良いこと。

- 認可されたクライアントは、共有フォルダの追加と Anki の有効化ができます。それが機能ですが、
  同時に届く範囲でもあります。取り消すには `authorizedClients` から指紋を消してデーモンを
  再起動します。
- ペアリングコードはターミナルとローカルネットワークを通ります。信用できるネットワークで、
  一度だけペアリングしてください。以後、コードはもう関係ありません。
- 設定ファイルには API キーが平文で入ります。あなたのユーザーだけが読める権限で書かれますが、
  それは別のアカウントから守るもので、あなた自身から守るものではありません。

## 困ったとき

**「that room is not open」と言われる。** コードが期限切れか、使用済みか、アドレスが別の
何かを指しています。パネルの現在のコードを確認してください。コードは 15 分ごとに入れ替わり
ます。

**アドレスそのものに届かない。** デーモンは `0.0.0.0` で待ち受けているので、怪しいのはまず
ファイアウォールです。ポートを開けるか、ブラウザが別のマシンにあるときは `localhost` ではなく
パネルが出しているアドレスを使ってください。

**Anki に届かないと言われる。** AnkiConnect が Anki に入っていて、Anki 自体が開いている
必要があります。既定のポートは 8765 で、AnkiConnect の設定と `config.json` の両方で変え
られます。

**AI が「何も聞いていない」と言う。** Ollama なら `ollama serve` が動いていて、`config.json` の
モデルが pull 済みである必要があります。

**ファイル操作が `permission` や `denied` と答える。** パスが共有フォルダの外へ出ています。
シンボリックリンク経由かもしれませんし、ホスト自身に権限がないのかもしれません。どちらも
柵が働いている音です。

**`bun run start` がポート使用中と言う。** 4287 で誰かが待ち受けています。`--port 5000` を
渡すか、もう 1 つのデーモンを止めてください。

## 開発

```sh
bun run start   # デーモンを起動
bun test        # エンドツーエンドのテスト
bun run check   # 型
```

テストは参照クライアントです。空きポートと一時的な設定ディレクトリで本物のデーモンを起動し、
本物の WebRTC ピアでつなぎ、ペアリングしたあと、ファイルシステム、パスの拒否、シンボリック
リンクの脱出、ローカルの偽物に対する Anki の転送、1 語ずつ返す偽の Ollama に対する AI の
ストリームを確かめます。このテストを満たすならブラウザも満たします。両側が出会う場所は
`src/protocol.ts` しかありません。
