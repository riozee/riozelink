# RiozeLink

**[English](README.md) · 日本語**

RiozeLink は、あなたのパソコンで動かす小さなデーモンです。ブラウザの [riozeOS](https://rioze.dev)
へ、暗号化された専用の一本のリンクを開きます。そのリンクを通して riozeOS は、選んだフォルダを
ドライブとして読み書きし、AnkiConnect と話し、Ollama や OpenAI 互換のエンドポイントへ自分の
キーで AI のチャットを送れます。アカウントは要らず、ルーターのポートを開ける必要もありません。
デーモンのほうから合図用のサーバーに名前を登録し、`peerjs` ライブラリと同じやり方で、
ブラウザがやってくるのを待ちます。

```text
 あなたのパソコン                       ブラウザ
┌──────────────────────┐              ┌──────────────────────┐
│  ~/Notes      ───────┼── WebRTC ────┼─► /riozeos/drives/   │
│  AnkiConnect  ───────┼── 暗号化 ────┼─► notes              │
│  Ollama       ───────┼── DataChannel┼─► Anki パネル        │
│  API キー (0600)     │      ▲       │   AI パネル          │
└──────────────────────┘      │       └──────────────────────┘
                              │                    riozeOS アプリ
                    合図用サーバーが一度だけ引き合わせる
                    （四つの単語で。以後は不要）
```

## なぜ使うのか

- **本物のファイル。** パソコンのフォルダが riozeOS のドライブとして現れます。読み、書き、名前を
  変え、消せます。riozeOS 自身のファイルはブラウザの中にあり、ブラウザはいつでもそれを消せます。
  共有フォルダはあなたのディスクなので、置いた場所にそのまま残ります。
- **プラグインに振り回されない Anki。** AnkiConnect はパソコンのループバックでしか待ち受けません。
  デーモンはその同じパソコンで動いているので、呼び出しをそのまま届けます。
- **モデルのある場所で動く AI。** Ollama はあなたのパソコンで動いています。OpenAI のキーも同じ
  パソコンに、あなただけが読める権限で保存されます。riozeOS が目にするのは `sk-...1234` までです。

## 必要なもの

- [Bun](https://bun.sh) 1.2 以降。デーモンは Bun が直接実行する TypeScript です。
- どのブラウザの、どこにある riozeOS でも。同じネットワークにいる必要はありません。
- 任意で、[AnkiConnect](https://foosoft.net/projects/anki-connect/) アドオンを入れた Anki と、
  ローカルモデルを使いたい場合の [Ollama](https://ollama.com)。

## インストール

```sh
git clone https://github.com/riozee/riozelink.git
cd riozelink
bun install
```

インストールせずに試すなら、そのまま起動できます。

```sh
bun run start
```

`riozelink` を `PATH` に置きたくなったら次をどうぞ。

```sh
bun link
```

GitHub から直接入れることもできます。

```sh
bun install -g github:riozee/riozelink
```

## はじめての接続、順番に

**1. デーモンを起動する。**

```sh
riozelink
```

ターミナルに小さなパネルが出ます。次の手順で必要なものは、そこに全部書いてあります。

```text
RIozeLink 0.3.0 · listening
signal   wss://0.peerjs.com/peerjs
words    amber-cobalt-summit-drift (14m 03s left)
clients  no clients yet
shares   none yet
config   ~/.config/riozelink/config.json
```

**2. フォルダを共有する。** 別のターミナルからでも、あとで riozeOS のアプリからでも構いません。

```sh
riozelink folders add ~/Notes --label Notes
```

**3. riozeOS からつなぐ。** riozeOS を開き、**RiozeLink** アプリを起動します。四つの単語を
打ち込んで Connect を押す。準備はこれで全部です。住所も、ポートも、慎重に写すコードも
ありません。

この裏側では次の順番で進みます。

1. その四つの単語が待ち合わせ場所の名前になります。デーモンとブラウザの両方が単語を
   ハッシュし、同じ id で合図用サーバーに登録します。サーバーが単語そのものを知ることは
   ありません。
2. ブラウザが ECDSA P-256 の鍵ペアを作り、秘密鍵は取り出せない形のまま IndexedDB に置きます。
   ブラウザの外には出ません。
3. 両側はそのサーバーを通して WebRTC の offer と answer を交換します。ここは紹介だけです。
   会話そのものは DTLS で暗号化された DataChannel の上を通り、サーバーはもう役目を終えます。
4. そのチャンネルでブラウザが `auth:hello` を送ります。デーモンは自分の公開鍵とノンス、
   そしてブラウザのノンスへの署名を返します。ブラウザはそれを検証するので、途中で応答した
   何かではなく、あなたのデーモンにつながったと確信できます。
5. 最初のペアリングでは、単語を知っている証明も添えます。単語を PBKDF2 でのばした鍵で
   デーモンのノンスに HMAC をかけて送るのです。単語そのものは回線を渡りません。同じ
   メッセージにブラウザの鍵の署名も乗るので、保存される鍵はそのまま使われる鍵です。
6. デーモンは両方を確かめ、ブラウザのフィンガープリントを `authorizedClients` に書いて、
   その場で単語を引退させます。次の機器のために新しい四語が現れます。

**4. 使う。** 共有したフォルダは riozeOS のファイルエクスプローラーで
`/riozeos/drives/remote-notes` として現れます。そこでする読み書きは、そのまま選んだフォルダに
届きます。

## 日常の使い方

### 再接続

riozeOS のアプリを開いて Connect を押すだけです。打ち込むものは何もありません。ブラウザと
デーモンは、おたがいのフィンガープリントから作った名前で登録します。その名前を計算できるのは
この二者だけです。ブラウザはペアリングのときに保存した鍵で自分を証明します。デーモンの身元は
再起動を越えて残り、ブラウザは最初のペアリングで見た指紋を覚えていて、その名前で居座った別の
マシンは拒まれます。

### 共有フォルダを増やす

ターミナルから。

```sh
riozelink folders add ~/Documents/recipes
riozelink folders list
riozelink folders remove recipes
```

riozeOS 側では RiozeLink アプリの **Drives** タブが同じことをリンク越しに行います。認可された
クライアントはフォルダを追加できます。これは本物の権限なので、ペアリングは「このマシンへの
鍵を渡すこと」だと思ってください。取り戻したいときは、設定ファイルの `authorizedClients`
からそのクライアントを消してデーモンを再起動します。

### Anki

アプリの **Anki** タブか設定ファイルで有効にします。頼むまでは切れています。有効な間、
デーモンは 5 秒ごとに `127.0.0.1:8765` を調べ、Anki が開いた・閉じたその瞬間を接続中の
すべての riozeOS に知らせます。アプリの表示はひとりでに灯ります。無効な間は、ペアリング済みの
クライアントにも `denied` と答えます。

コレクションの中身がどこかに保存されることはありません。呼び出しは転送され、それきりです。

### AI

**AI** タブにも専用のトグルがあり、切れた状態から始まります。そのうえで 2 つのプロバイダーです。

- **Ollama。** エンドポイントの初期値は `http://127.0.0.1:11434` です。キーは不要で、チャットは
  トークンごとに流れてきます。
- **OpenAI 互換。** `stream: true` の `/v1/chat/completions` を話すエンドポイントなら、自前の
  ゲートウェイでも構いません。キーは暗号化された回線を一度だけ渡り、`0600` の権限で
  `config.json` に書かれ、二度目以降は伏せ字でしか読まれません。

キーの設定は書き込みきりです。アプリがダイアログを開いてキーを送り、以後は `sk-...1234`
しか見えません。入れ替えるときは **Set a new key**、消すときは **Clear** です。

### ウェブを読む

riozeOS のブラウザは、ページをデーモンに頼むことができます。ウェブの多くは
`X-Frame-Options` や `frame-ancestors` でフレームに入ることを拒みますが、デーモンはこの
マシンの回線でページを取りに行き、枠の中に置ける文書にして返せます。返すのは本文ひとつ
だけで、拒まれる原因になった meta タグを外し、相対 URL が正しく解けるように `<base>` を
足し、リンクのクリックをアプリへ知らせる小さなスクリプトを添えます。

本文はファイルと同じように 45 KiB ずつ DataChannel を渡ります。文書だけが渡り、画像や
スタイルシートやスクリプトは本来のアドレスのまま、それぞれの配信元から読み込まれます。
ディスクには何も書かず、セッションをまたいで何も残しません。タブが開いている間、1 つの
セッションにつき 4 ページまで保持します。

もうひとつ、`web:probe` という軽い呼び出しがあります。ページのヘッダーだけを読んで、
フレームを拒む規則があるかを答えます。ブラウザの中からは拒まれたフレームと空のフレームを
見分けられないため、すぐ読み込み終わったページが拒否だったのかどうかを、ブラウザはこれで
確かめます。

この取得にクッキー入れはありません。サイトが公開していない資格情報を送ることもありません。
受け付けるのは `http` と `https` の URL だけです。この経路でページにログインすることは
できず、アプリはそう見せかけずに、その旨を画面に書きます。

## 設定ファイル

初回起動で `~/.config/riozelink/config.json` が作られます。手で編集する前提のファイルです。
読めない値は既定値に戻るだけで、デーモンが止まることはありません。

```json
{
	"version": 1,
	"hostName": "rioze-macbook",
	"signal": "wss://0.peerjs.com/peerjs",
	"folders": {
		"notes": { "label": "Notes", "path": "/Users/rioze/Notes" }
	},
	"anki": { "enabled": false, "port": 8765 },
	"ai": {
		"enabled": false,
		"provider": "ollama",
		"endpoint": "http://127.0.0.1:11434",
		"model": "llama3.2",
		"apiKey": ""
	},
	"authorizedClients": {
		"9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08": {
			"label": "Browser",
			"pairedAt": 1789000000000
		}
	}
}
```

同じ場所に `identity.json` があり、デーモン自身の鍵ペアが入っています。これは大切に。差し替える
と、ブラウザが固定した指紋が消えるので、すべてのブラウザがもう一度ペアリングを求められます。

`RIOZELINK_CONFIG_DIR` を設定すると両方のファイルを別の場所へ移せます。テストが本物のホーム
ディレクトリに触らないのも、これを使っているからです。

## コマンド

| コマンド                                        | すること                                                     |
| ----------------------------------------------- | ------------------------------------------------------------ |
| `riozelink`                                     | デーモンとターミナルパネルを起動します。                     |
| `riozelink --signal ws://host:9000`             | 既定以外の合図用サーバーで待ち合わせます。                   |
| `riozelink --stun stun:stun.l.google.com:19302` | STUN サーバーを足します。頑固な NAT の向こうへ出るためです。 |
| `riozelink --quiet`                             | 単語を一度だけ出し、あとはログ行だけ流します。               |
| `riozelink folders list`                        | 共有中のフォルダを表示します。                               |
| `riozelink folders add <path> [--label Notes]`  | フォルダを共有します。                                       |
| `riozelink folders remove <id>`                 | 共有をやめます。                                             |
| `riozelink clients list`                        | 覚えているブラウザを表示します。                             |
| `riozelink clients revoke <name>`               | 名前ごと忘れます。                                           |
| `riozelink status`                              | 設定ファイルの要約を、クライアントも含めて表示します。       |

パネルでは `n` が新しい四語、`h` が最初の接続の手引き、`q` がデーモンの停止です。

## 待ち合わせ場所

WebRTC が引き継ぐ前に、両端を引き合わせる必要があります。どちらにも住所を尋ねられないので、
デーモンは合図用サーバーに名前を登録して待ちます。四つの単語を持つブラウザは、それを同じ名前に
ハッシュし、自分の名前を登録して、そちらへ offer を送ります。サーバーは offer と answer と ICE
の候補を行き来させ、二人が直接話し始めたらもう場面から降ります。次からの再接続に単語は要りません。
両側がフィンガープリントから計算する名前は、ほかの誰にも当てられないからです。

既定は `wss://0.peerjs.com/peerjs`、`peerjs` ライブラリ自身が使っている公開の PeerServer
クラウドです。登録も支払いも要らず、運ぶのは紹介だけです。自前で動かすのもコマンドひとつ、
コードは不要です。両端から届くマシンで `npx peerjs --port 9000` を起動し、デーモンを
`riozelink --signal ws://your-host:9000` で立ち上げ、アプリの _Meeting point_ 欄に同じ住所を
入れてください。どちらを使っているかはパネルとアプリの Overview タブに両方出るので、二人が
同じ場所にいるかを見比べられます。

正直な限界がひとつあります。この仕組みに TURN サーバーはありません。TURN は、二つの端が
直接つながる道を見つけられないときに、通信そのものを運ぶ役です。両方の網が対称 NAT や
キャリアグレード NAT のときがそれにあたります。家の Wi-Fi でも、スマホのテザリングでも、
同じマシンで二つ動かすのでも、直接の道は見つかり、すべて普通に動きます。相性の悪い網どうしでは
つながらないことがあり、そのときアプリはチャンネルが開かなかったと伝えます。確実な回避策は
両方の機器をひとつのテザリングにつなぐことです。本気で直すなら TURN サーバーを動かすことになり、
お金がかかる唯一の部品なので、いまは意図して入れていません。

## 仕組み

### 部品たち

| 部品             | ある場所                       | すること                                                                                                      |
| ---------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 四つの単語       | `src/words.ts`                 | 素直な英単語 534 語。1 フレーズ 4 語で約 36 ビット。                                                          |
| 合図             | `src/signal.ts`                | 名前ごとに 1 本の登録。心拍と、間を置いた再接続。                                                             |
| WebRTC リンク    | `src/peer.ts`                  | ブラウザの offer に答え、候補を流し、DataChannel を渡します。                                                 |
| 認証             | `src/session.ts`               | hello、proof、pairing。ほかのメッセージはこの後ろで待ちます。                                                 |
| ファイルシステム | `src/vfs.ts`, `src/sandbox.ts` | パスの柵、分割読み書き、パートファイル、変更の監視。                                                          |
| Anki             | `src/anki.ts`                  | トグルひとつ、5 秒ごとの確認、ループバックへの POST。                                                         |
| AI               | `src/ai.ts`                    | 2 つの方言を 1 つのストリームに。キーはここに残ります。                                                       |
| ワイヤ契約       | `src/protocol.ts`              | 両側がクライアントとディスパッチャを組み立てる、ただ 1 つのファイル。名前とペアリングの証明もここで導きます。 |

riozeOS 側は riozeOS リポジトリの `com.riozelink.svelte` アプリです。そのリモートバックエンドは
ローカルのファイルシステムと同じ `VfsBackend` を実装しているので、ファイルエクスプローラーは
ドライブが遠くにあることを知りません。

### ファイルを 1 つ読む、その一生

1. riozeOS がファイルシステム層に `/riozeos/drives/notes/sub/list.txt` を求めます。
2. マウントテーブルが、パスがリモートドライブの中だと気づき、接頭辞を外してリモートバック
   エンドに渡します。バックエンドが見るのは `/sub/list.txt` です。
3. バックエンドは共有 ID とオフセットを添えて `vfs:read` を送り、最大 45 KB を求めます。
4. デーモンはパスを正規化し、存在する一番深い部分までさかのぼって、OS にその実体の場所を
   尋ねます。実体が共有フォルダの外なら、呼び出しごと拒否します。シンボリックリンクで
   何かを持ち出すことはできません。
5. デーモンはその一片を読み、base64 にして返します。クライアントは `done` が来るまで
   頼み続けます。

1 メッセージ 45 KB というのは、切りのいい数字ではなく、理由のある数字です。base64 で 3 割
ほど増え、WebRTC の実装によっては 64 KB がメッセージの上限なので、その下に収める必要が
あります。どこでも通る一片は、紙の上で速い一片に勝ります。

### ファイルを 1 つ書く、その一生

書く方向は慎重です。各一片は、対象と同じフォルダの隠しファイル
`<name>.riozelink-part-<id>` に落ちます。最後の一片が届くまで本物のファイルには触らず、
最後の仕上げは rename 一回だけです。rename は起きるか起きないかのどちらかなので、途中で
切れたアップロードが「本物のつもりの半端なファイル」を残すことはありません。

パートファイルはクライアントからは見えず、持ち主のセッションが終わると消えます。途中で
kill されたデーモンは 1 つ残すことがあります。次の起動が 1 時間より古いものを掃除します。

### 再接続と身元

デーモンは最初の起動で ECDSA P-256 の鍵ペアを `identity.json` に作ります。ブラウザは最初の
ペアリングで見たフィンガープリントを固定し、接続のたびに照合します。同じ住所の別のマシンが
静かに取って代わることはできません。

戻ってくる側に単語は要りません。両端が登録する名前こそが「そこに居ていいのは誰か」の証明
だからです。二人の公開フィンガープリントを合わせてハッシュし、その名前に行き着けるのはその
二者だけです。デーモンはペアリング済みのブラウザごとにそんな登録をひとつ持ちます。会った
ことのないクライアントには、ノックする場所がありません。

### 四つの単語

フレーズは 534 語のリストから 4 語、約 36 ビットです。誰かが総当たりでたどり着ける
量ではありません。間違えれば 10 回で四語が入れ替わり、15 分で寿命が尽き、使われた
その瞬間に引退します。それでいて、ターミナルから読み上げられ、スマホで打てる長さです。

四語は三つの仕事を同時にこなします。人が読むもの、ハッシュすれば待ち合わせ場所の名前、
そしてそのターミナルの前にいたことの証明です。証明は PBKDF2 でのばした鍵による HMAC で、
単語そのものはどちらの向きにも回線を渡りません。

### 複数のブラウザを同時に

1 つのデーモンが複数の riozeOS を同時に相手にします。接続はそれぞれ自分のセッションを持ち、
認証状態も、アップロード中のパートファイルも、AI のストリームも別々です。デーモンが
クライアント同士を引き合わせることはありません。共有されるのは接続数という数字だけで、
ほかのクライアントについて知れるのもそれだけです。

### 変更を眺める

共有フォルダはホスト側で監視されます。変更は 0.25 秒ぶんまとめられ、接続中のすべての
クライアントへ `vfs:changed` として届きます。`fs.watch` は作成と削除を見分けられないので、
rename には `stat` で答えます。名前がいま存在するなら、現れたのです。純粋な rename は削除と
作成として届きます。クライアントの場所から見れば、それは本当のことです。

## セキュリティについて、正直に

このリンクは仕組みとして閉じています。DataChannel は 2 つのピアの間で DTLS により暗号化され
るので、合図用サーバーが運ぶのは紹介だけです。どのセッションも、ほかのどんな
メッセージに答える前に対話の認証を通ります。両側が相手の選んだノンスに署名するので、再生や
中間者を挟むことはできません。ペアリングでは、四語を知っている証明も添えます。これが、
正しい待ち合わせ場所にたまたま居合わせた誰かを止めるものです。

デーモンが誰に頼まれてもしないこと。

- 共有したフォルダの外のパスに触れること。
- シェルコマンドの実行、ポートを開くこと、ネットワークの探索。
- API キーを伏せ字以外の形で返すこと。
- 設定ディレクトリの外に自分のファイルを書くこと。

知っておくと良いこと。

- 認可されたクライアントは、共有フォルダの追加と Anki の有効化ができます。それが機能ですが、
  同時に届く範囲でもあります。取り消すには `riozelink clients revoke <name>` を使い、
  デーモンを再起動します。
- 四つの単語は、生きている間は秘密です。自分が見ているターミナルでペアリングし、鍵を渡して
  いいと思えない相手には読み上げないでください。
- 合図用サーバーに見えるのは、「どこかの名前で二つの接続が出会った」ことまでです。単語も、
  ファイルも、チャットも、鍵も見えません。ただし既定ではそれは他人のマシンです。紹介を
  覗かれるのが気になるなら、自分のものを動かしてください。
- 設定ファイルには API キーが平文で入ります。あなたのユーザーだけが読める権限で書かれますが、
  それは別のアカウントから守るもので、あなた自身から守るものではありません。

## 困ったとき

**「pairing failed. Check the four words on the host and try again.」と言われる。** フレーズは
15 分で切れ、ほかの機器が使った瞬間に引退します。パネルの現在の四語を確認してください。

**四語を打っても何も起きない。** 両端は合図用サーバーで待ち合わせます。デーモンが
`wss://0.peerjs.com/peerjs` に届かないときは、ログの再試行の行を見てください。自分で
サーバーを動かしているなら、両端に同じ住所を教えているかを確かめてください。どちらを
使っているかはパネルとアプリの Overview タブに両方書いてあります。

**アプリが「チャンネルが開かなかった」と言う。** 二人は見つかったけれど直接の道を作れない
ときの言葉です。両方の網が対称 NAT やキャリアグレード NAT だと起きます。これを書いている
時点のこの仕組みには TURN サーバーがないので、頼れる回避策は両方の機器をひとつのテザリングに
つなぐことです。変わった網では `--stun stun:stun.l.google.com:19302` も試す価値があります。

**Anki に届かないと言われる。** AnkiConnect が Anki に入っていて、Anki 自体が開いている
必要があります。既定のポートは 8765 で、AnkiConnect の設定と `config.json` の両方で変え
られます。トグルが入っていれば 5 秒ごとに確認するので、Anki を開けば表示はひとりでに
灯ります。

**AI が「何も聞いていない」と言う。** Ollama なら `ollama serve` が動いていて、`config.json` の
モデルが pull 済みである必要があります。ゲートウェイにも専用のトグルがあり、既定はオフです。

**ファイル操作が `permission` や `denied` と答える。** パスが共有フォルダの外へ出ています。
シンボリックリンク経由かもしれませんし、ホスト自身に権限がないのかもしれません。どちらも
柵が働いている音です。

**同じ身元のデーモンがすでに登録されていると言われる。** 同じ設定ディレクトリを使う
デーモンが 2 つ動いています。片方を止めるか、`RIOZELINK_CONFIG_DIR` で別の場所に
向けてください。

## 開発

```sh
bun run start   # デーモンを起動
bun test        # エンドツーエンドのテスト
bun run check   # 型
```

テストは参照クライアントです。本物の PeerServer と本物のデーモンを空きポート・一時的な設定
ディレクトリで起動し、本物の WebRTC ピアでつなぎ、実際の四語でペアリングしたあと、登録、
ファイルシステム、パスの拒否、シンボリックリンクの脱出、ローカルの偽物に対する Anki の
転送、1 語ずつ返す偽の Ollama に対する AI のストリームを確かめます。このテストを満たすなら
ブラウザも満たします。両側が出会う場所は `src/protocol.ts` しかありません。
